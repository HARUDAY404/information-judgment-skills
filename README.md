# Information Judgment Skills

一套把碎片信息转化为个人判断与内容实验的四阶段工作流。

```text
外部信息 → information-radar → claim-auditor → judgment-journal → content-lab
             值得看吗？       证据到哪？       我怎么看？        如何表达与验证？
```

## 四个 Skills

- `information-radar`：围绕当前问题监测信息，聚类去重，在注意力预算内选出少量候选信号。
- `claim-auditor`：将内容拆成可检查的主张，追溯来源，寻找反证，标注证据边界与不确定性。
- `judgment-journal`：先保留用户的原始判断，再通过反方审视、预测和事后复盘提升校准能力。
- `content-lab`：把判断转化为面向具体受众的验证型或探索型内容实验。

它们可串联，也可单独调用。不要把四类分数合并成一个总分：Radar 评估注意价值，Auditor 评估证据，Journal 记录个人置信度，Lab 评估内容表现。

## 安装

将任意 Skill 目录复制到支持 Agent Skills 的工具中。在 Codex 中可放入 `~/.codex/skills/`。其他工具如不支持标准 Skill，可将对应 `SKILL.md` 作为工作流指令使用；工具、权限和自动化能力需单独适配。

## 建议的7天试运行

- Radar 每日最多输出 5 条；宁可为 0，不填充日报。
- 每日最多选 1 条进入 Claim Auditor。
- 每日最多形成 1 条 Judgment Journal 记录。
- Content Lab 只在确实要公开表达或测试需求时调用，不必日更。
- 第7天复盘使用负担、噪声、重复、遗漏和真正促成的行动；不在一周内声称已证明长期效果。

## 设计原则

- 问题优先，博主和平台只是信源。
- 审计具体主张，不给一个人贴永久的“可信/不可信”标签。
- 保留原始链接、反证、未知和历史版本。
- AI 可以结构化材料和充当反方，不得伪造用户的初始判断。
- “严格程度”改变收录阈值和数量，不随意改变同一条信息的基础分数。
- 规则更新必须保留版本并回放固定测试集，不允许系统静默自我改写。
